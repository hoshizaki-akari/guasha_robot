> **对应关系**：与学术报告 R13.0 的 **0—17 章逐章对应**，包含该报告的全部 12 项文献、10 个编号公式、9 条假设、11 条决策、6 个工作包与各章表格。每章按“概念—类比—数字或实例—常见误读—自测与答案”展开；末尾自动附该章**原表和公式核对区**，防止学术细节遗漏。**研究边界**：本轮只分析公开室内数字笔迹和本地合成测试；没有真实人体、实体墨线、FR5 实测或人体安全结论。

## 0. 先认识本轮到底解决了什么：图上能走多远，不等于机器人能走多远

想象你在地图上用荧光笔画了一条弯弯曲曲的路线。有些地图格子有海拔高度，有些没有。上一轮只数“有海拔的格子占多少”，本轮进一步问：**没有海拔的格子是不是连成大片？从缺测格子沿着荧光笔标记，走几步才能找到一个有海拔的格子？**这叫“沿标注图的最短距离”，并不是现实世界里走了几米。

三张真实室内图分别叫 `bedroom_12`、`kitchen_22`、`livingroom_01`。它们不是人体照片，所谓 scribble 是人用软件在图片上画的数字语义标注，不是拿笔画在皮肤上的线。本轮读取了它们的原始深度 PNG 和 scribble PNG。八邻接统计发现，第一张图 295 个缺深度的标注像素中，有 70 个在**标注图内部**走不到任何有效深度点；其余可达的缺测点，距离最近有效点的 95 分位是 67 步。第二张是 87/226 不可达、18 步；第三张是 83/485 不可达、65 步。

这个发现不等于“机器人轨迹误差 67 毫米”。一跳可以是横着移动一个像素，也可以是斜着移动一个像素；每像素对应的毫米长度随相机内参和距离而变；更关键的是，图像上交叉的两条标记可能不属于同一笔。**本轮真正学到的是如何找到值得重新拍摄的区域，而不是如何凭空补出准确的三维点。**

另一个新收敛来自官方机器人手册：FAIRINO 已有 `FT_Control` 恒力控制接口。因此“自己写一个 PID 就是博士创新”并不成立。我们应该先验证官方基线，再考虑复杂视觉—力觉算法。返程“轻力”还需要先卸载、确认状态，并与离面返程比较；不能直接拿厂家示例力值去接触人体。

**自测 0**：图上 67 跳可以写成 67mm 吗？**答案**：不能；还缺相机尺度、真实笔顺、深度正确性和独立测量。**进阶题**：为什么研究报告写“本轮有真实数据”，又写“本地真实数据复算未通过”？因为真实 PNG 在只读连接器环境完整解码；本地 Python 程序只跑了合成数组，两种证据不能混同。

## 1. 从 R12 继承研究决策：为什么不能每轮都换一个漂亮指标

把连续科研想成修建一条桥。上一轮发现桥面木板不是一条真正可行走的路线，于是决定区分**地图上的格子连接**和**人要从哪里走到哪里**。这一轮不能忘记这个结论，改成“图最短路就是实际步行路线”。R12 的 `OrderedStroke` 是用户真正希望执行的有序笔划；`SupportGraph` 是像素之间的支持关系。两者像“导航指令”和“道路网”，相关但不相同。

本轮先阅读上一轮的研究报告、教学讲义、决策追踪文件和代码，重点追踪六件事。第一，R12 已推翻连通分量等于笔划；第二，连续缺测段应该优先重观测；第三，直接深度加拒绝是强基线；第四，刮板有宽度，不只需要中心线；第五，时间与坐标版本不能丢；第六，真实 PNG 本地复算、独立激光真值、实体墨线和 FR5 试验仍未完成。

本轮实际推进了第二件事：把“连续缺测”细化成缺测岛和到最近有效点的图距离。但还没拍第二张照片，也没做激光真值，因此只能说“给出了候选重观测优先级”，不能说“已经提升了毫米精度”。R12 的旧仓库禁写决策也保持不变。可见 GitHub 仓库中没有一个被明确确认为独立新研究仓库，所以不会因为某仓库可写就随意使用。

**类比**：体检报告上出现异常指标，不等于医生已经治疗成功。缺测图指标是诊断提示；真实三维曲面重建和接触执行才是治疗前的后续关卡。

**自测 1**：如果图上有一条闭合线，机器人能自动知道从哪里开始、往哪个方向走吗？**答案**：不能；闭合图本身没有起点、方向和操作者意图。**补充**：报告第 1 章的继承表逐行告诉你哪些“保留”、哪些“只推进到软件层”，不要把未通过项当成功。

## 2. 十二项文献怎么读：全文、摘要、官方手册和真实二进制文件的区别

科研最常见的错误不是公式写错，而是把“看过网页”说成“读过论文全文”，或把“厂家有接口”说成“我们的机器人已经跑通”。本章把报告的 `L13-01` 至 `L13-12` 逐项翻译成白话。

**L13-01 TUM 数据集**：本轮真的从只读 GitHub 连接器拿到了六个完整 PNG 文件，在隔离 JavaScript 中解码并计算。可以说“真实室内像素已分析”，不能说“本地 Python 复算完成”或“皮肤画线已测试”。**L13-02 README**：这是数据作者的完整说明，告诉我们有 154 张室内图、640×480 分辨率、深度单位毫米；它不是深度误差的真值证书。

**L13-03 Koch 等 2018/2019**：前一轮核读过方法章节，本轮只新核出版记录和摘要；它提醒我们深度评价要看平面、边界和绝对尺度，不能把这些已有指标当原创。**L13-04 iBims-1 官方说明**：这里有 100 组室内激光深度参考、边界和平面掩码；但是本轮没有下载，也不能拿它的激光图直接和 TUM 的另一间卧室逐像素相减，因为不是同一个场景。

**L13-05 Park 2014** 和 **L13-06 Wang 2023**：只按摘要确认“用 RGB 引导深度补洞”和“动态滤波”已有先例。不能引用没读到的消融实验、准确率或运行速度。**L13-07 Vasudevan 2024**：摘要提醒深度非零也可能是飞点，即深度相机在物体前后边界处产生看似有数值但不属于真实表面的点。**L13-08 Tang 等 2007**：机构摘要说明混合像素/边界检测有多种方法且没有通用万能方案。它们共同说明：不能凭深度非零就认定三维正确。

**L13-09 FAIRINO 官方 SDK**：本轮读到原始六维力 `FT_GetForceTorqueOrigin`、参考系六维力 `FT_GetForceTorqueRCS`、零点 `FT_SetZero`、参考坐标系 `FT_SetRCS`、碰撞保护 `FT_Guard`、恒力 `FT_Control` 等完整接口说明。**L13-10 官方探测示例**：官方特别提醒示例模板不应直接运行，必须针对设备和安全要求修改。**L13-11 NIST**：教我们对误差的相关性负责，不能用多次重复把共同偏差平均掉。**L13-12 R³DC 2026 Workshop 项目页**：它已经公开讨论深度可靠性与不确定性；本轮只看项目介绍，不能称论文全文已读，更不能照搬其性能数字。

**类比**：菜单写有某道菜（接口存在），不等于你已经吃过它（实机运行）；朋友告诉你菜好吃（摘要），不等于你掌握了完整做法（论文全文）。

## 3. 数据里到底有什么：像素、深度、数字笔迹和真实墨线

相机图像由像素组成。RGB 像素记录颜色；深度图记录该方向上的距离。TUM 数据集中深度图是 16 位整数，README 说明单位为毫米。scribble 图用不同索引表示数字语义笔迹。`S(p)≠0` 表示这个像素被标注；`D(p)>0` 只表示深度文件中有非零数字，不代表数值正确。我们还排除了四周两像素边框，避免在局部邻域计算时越界。

用生活类比：`S(p)≠0` 像地图上被荧光笔涂到的地方；`D(p)>0` 像那格地图上写了海拔数；**海拔数可能写错**，而且地图不是你实际走过的路线。实体画线还要处理墨水反光、皮肤运动、毛发、照明、不同笔划重叠等问题，这些在数字 scribble 里没有被验证。

研究问题 Q13 不是“能不能在人体上刮痧”，而是“能不能在没有独立真值时诚实描述缺测结构”。研究问题 Q13-F 则是“即使机器人 SDK 有恒力功能，哪些信息缺失时也必须拒绝进入下一阶段”。


**再把三种“线”摆在一起比较**：第一种是图片上的数字 scribble，它常常是为了语义分割而画的提示，不保证每条线对应一次连续手部动作；第二种是操作者在屏幕上按顺序点选的路线，它可以有时间顺序和方向，但对应像素的深度可能缺失；第三种是操作者在真实弯曲仿体上画出的墨线，相机会看到墨线的颜色，却仍需确认墨线在三维曲面上的位置。未来自动穴位/点位识别属于第四类问题，必须等前面三种对象的误差和接口建立以后再研究。

**为什么不直接对缺测像素插值？**想象在桌沿上从前景跨到背景，两个相邻像素的深度可能分别是 0.6m 和 1.6m；把中间填成 1.1m，会制造一个实际不存在的空间点。即使缺测像素附近很多地方有数值，也不代表中间有平滑曲面。真正的验证需要独立测量的非人体曲面真值和深度边界标签。

**自测 3**：如果深度为 1738，说明实际表面距离一定是 1738mm 吗？**答案**：不能；只说明源文件有该数值，还需要相机尺度、配准、边界/飞点与独立参考。**例子**：一个有深度的点可能落在前景/背景混合边界，插值到皮肤表面会造成错误接触。

## 4. 真实 PNG 从哪里来，为什么“SHA 一致”还不是精度真值

本轮从 TUM 公开仓库的 `LabeledImages` 目录获取 `bedroom_12_depth.png`、`bedroom_12_scribbles.png`，另外两个场景同理，共六份。GitHub 提供每份文件的 **Git blob SHA-1**，它相当于文件内容的指纹。与上一轮记录一致，说明这轮读到的是同一版本的源文件。报告的来源表列出每一份指纹和像素分母；三个场景分别有 1482/1187、1003/777、803/318 个“标注/有深度”像素。

但**同一个错误文件每次读出来 SHA 也一样**。因此 SHA 只能证明文件版本一致，不能证明深度正确，更不能证明相机与机器人标定正确。PNG 需要先解压；本轮在连接器的隔离 JavaScript 中完成 base64 解码、zlib/DEFLATE 解压、PNG 行滤波逆变换以及 16 位大端深度读取。对照上一轮计数相符，这是可信的**同源交叉检查**。

本地另写了 Python `round13_gap_and_gate.py`，它会先验 SHA 再计算；但容器访问原始文件的网络 DNS 不通，**真实文件没有在本地落地**。我们在本地只运行了合成数组测试。区分运行环境是科研可复现性的一部分：别人可以按文档下载文件运行程序，但我们不能把“别人将来能运行”写成“我们今天已经运行”。

**自测 4**：SHA 一致、像素计数一致，能否证明三维误差小于 1mm？**答案**：完全不能；它们只证明文件/统计的同源一致性。**进阶**：为什么报告保留每个场景的 SHA？方便未来真正拿到字节时逐一确认版本，避免不同版本数据被错误比较。

## 5. 公式 R13-1～R13-4：从数字笔迹建图，再找“缺深度的岛”

先学三个字母。`A` 是所有被数字笔迹标记的像素集合；`V` 是其中深度大于零的像素集合；`G_k` 是把 `A` 里的像素按某种相邻规则连起来的图，`k=4` 表示只连上下左右，`k=8` 再加四个对角。这就是 **R13-1**。图不是实体路线，它没有自动携带起点、终点和运动方向。

**R13-2** 里的 `d_k(p)` 表示：从缺深度像素 `p` 出发，沿数字笔迹图的边，走到任意一个 `V` 中的点，至少要走几步。把所有有深度点同时放进 BFS 队列，可以一次算出所有缺测点的最近距离。BFS 是“先找一步能到的，再找两步能到的……”的广度优先搜索。若根本走不到，记 `∞`（无穷大），不是距离非常大，而是**图中没有通路**。

**R13-3** 定义两个统计量：`U_k` 是缺测点中“不可达”的比例；`P95_k` 是**可达缺测点**最短距离的 95 分位。假设 100 个缺测点中 40 个不可达、60 个可达，那么 `U=40%`，P95 只能在那 60 个点里计算；如果只说 P95 很小，就隐瞒了 40 个完全不可达点。**R13-4** 进一步只保留缺测点，再用图搜索把相连的缺测点分成一座座“岛”，`M_k` 是最大岛的像素数。

**手算例子**：一条横向五像素笔迹 `[有, 缺, 缺, 缺, 有]`，从两端同时 BFS，三个缺点的最短距离分别是 `[1,2,1]`，没有不可达点；缺测岛只有一个，大小 3。若五个都缺，五个都不可达，最大岛大小 5。若笔迹在图像上斜着走，四邻接可能断开，八邻接则可能连起来。

**重要误读**：`d=2` 不等于 2mm，也不等于能安全用两点线性插值；缺深度的两个像素可能跨越真实物体边界。**自测 5A**：六个缺点里两个不可达，`U` 是多少？**答案**：1/3。**自测 5B**：为什么要同时报告 `U` 和 `P95`？**答案**：P95 丢掉不可达样本，可能只剩容易的点。**自测 5C**：BFS 为什么适合无权图？**答案**：每条边代价都记作一步，按层扩展可找到最少边数；若边有不同实际长度，应改用带权最短路而不是把斜边当横边。

## 7. 真实结果 B：为什么四邻接 P95=9、八邻接 P95=65 不矛盾

四邻接像在棋盘上只准“车”走上下左右，八邻接像“国王”还能走斜线。假设标记主要沿斜对角延伸，四邻接会把它拆成许多小段：远处的缺测点可能被判为“不可达”，根本**不进入 P95 计算**；八邻接把斜线连起来，远处缺测点变为“可达但距离很远”，反而使 P95 变大。

这正发生在 `livingroom_01`：四邻接不可达 387 个、可达只有 98 个、P95=9 跳；八邻接不可达 83 个、可达 402 个、P95=65 跳。**不能说八邻接把算法精度从 9mm 变差到 65mm**，因为两者都不是毫米，而且被统计的缺测点集合不同。`kitchen_22` 的四/八最大缺测岛从 20 增至 61，也只是连通规则改变了岛的合并方式。

**类比**：一个考试只让 10 个容易题参加平均，另一个考试把 40 个困难题也纳入平均，平均分下降不代表第二次学生退步；样本集合变了。科研里这叫**选择性样本偏差**。正确比较要在固定样本上评价，或者至少同时报告被排除的数量。

**自测 7**：在 `livingroom_01` 中，哪种邻接让更多缺测点进入 P95？**答案**：八邻接（402 对 98）。**进阶**：为什么不能简单选“P95 数字较小”的规则？**答案**：可以通过让困难样本不可达而人为降低 P95，造成错误路线选择。

## 8. 公式 R13-5～R13-7：图像一格到底是多少毫米？误差从哪里来？

先想象相机是一只眼睛。像素 `(u,v)` 指定视线方向；深度 `z` 告诉你沿视线有多远。**R13-5** 用相机内参矩阵 `K` 把 `(u,v,z)` 变成相机坐标 `p_C`。`f_x,f_y` 是以像素为单位的焦距，`c_x,c_y` 是主点。只有这些参数正确，才能把“图上走一格”换成三维方向上的实际距离。

教学数字：假设 `z=0.7m`、`f_x=600px`，横向一像素约 `z/f_x=0.001167m=1.17mm`。这是**随手设定的假想相机**；不是这次 TUM 的实测内参，更不是“1.17mm 误差”。真实曲面会弯，深度会变化，斜着走的欧氏距离是另一个量；如果两条数字笔迹交叉，图最短路还能“抄近路”。

**R13-6** 的 `Σ_p` 是三维位置的不确定度协方差，`Σ_zuv` 表示深度和像素定位的不确定度，`Σ_K` 表示内参误差，`Σ_T` 表示手眼和机器人变换误差。`J` 是雅可比矩阵：你可以把它理解成“输入参数改动一点，输出会跟着改动多少”的换算表。`J Σ J^T` 就是把输入不确定度传递到三维输出的常用一阶近似。**共同偏差**不会因为重复拍摄 100 张照片就自动消失。

**R13-7** 再把时间错配加入：机器人在动，晚 10ms 才读到相机图，位置会错开大约“速度×时间”；如果同时旋转，还要考虑角速度叉乘观测点到转轴的向量。标定错误还会额外造成偏差。例子：仅作为量纲演示，若平移速度 0.1m/s、时间错配 0.01s，平移项是 1mm；但这并不是 FR5 实测误差，且旋转与标定项仍未知。

**自测 8A**：重复拍摄能消除固定安装偏差吗？**答案**：通常不能。**自测 8B**：为什么有深度不等于有可靠三维坐标？**答案**：还需 K、外参、时间、深度正确性与误差预算。**自测 8C**：`Σ` 的对角线和非对角线各表示什么？**答案**：对角线是各量方差，非对角线表示相关性；把非对角线强行设零可能低估总误差。

## 9. 算法比较：为什么我们不急着训练补洞神经网络

先看最简单方法 **B13-0 直接深度+拒绝**：能测到、经过基本审计的点才使用；测不到就拒绝或请人重拍。优点是不会在空白处凭空造数；缺点是可能放弃较多路径。**B13-1 缺测岛/图距离排序** 是本轮实际运行的新统计，它告诉我们哪片区域值得先拍第二次，但不保证第二次一定成功。**B13-2 人工有序笔划**需要记录人真正画线的顺序和方向，尚未取得实物数据。

**B13-3 RGB 引导补洞**像根据照片颜色推测被遮住的地形，可能让图更完整，但也可能把物体边界错误地抹平；已有 Park、Wang 等研究，不能当作我们的原创。**B13-4 主动重观测**像走到另一个角度重新看，可能解决遮挡，但前提是场景能配准、人体或仿体没有不可解释的运动。**B13-5 独立参考**像请测量员用另一套仪器测量真实高度，才有资格比较“谁的毫米误差小”。

**重要概念：风险—覆盖曲线**。算法可以选择只接受最容易的 10% 点，得到很低的错误率；但如果机器人需要完整轨迹，这可能没有实际价值。因此必须同时报告接受率（覆盖）和**已接受样本**的真实错误率（风险），而错误率必须靠独立真值来计算。本轮没有独立真值，所以没有生成虚假的算法精度排行榜。

**自测 9**：补洞算法把所有缺测像素都填上，能否说成功率 100%？**答案**：最多只能说输出覆盖达到 100%，不能说填出的深度正确、整条路径安全。**止损规则**：若直接深度+人工重观测在独立仿体盲测中已经满足预先规定的要求，就停止增加复杂补洞网络。

## 10. 公式 R13-8：为什么需要“有顺序的线”和“有宽度的板”

## 11. 公式 R13-9～R13-10：六维力觉、恒力、卸载与返程

腕部六维力传感器测三个方向的力和三个方向的力矩。它像一个秤加上一个能感知“往哪边扭”的装置，但不是贴在刮板边缘的每个位置都装了小压力计。**R13-9** 用积分表示：所有局部接触小力加起来得到合力 `F`；每个小力乘以到参考点的力臂，再加起来得到合力矩 `τ`。很多不同的局部分布可能产生相同的合力与合矩。

最简单的数学反例：左、中、右三点在 `-1,0,+1`。分布 A `(0,1,0)` 的合力 1、合力矩 0；分布 B `(0.5,0,0.5)` 的合力也是 1、合力矩也是 0，但最大单点载荷分别为 1 和 0.5。因此“六维腕力恒定”**不能**推出“皮肤接触压力均匀”。这里的 1 只是无量纲数学数字，绝不是人体力值建议。

厂商官方已经提供 `FT_Control` 恒力功能，所以我们的强基线不是自己从零写 PID，而是先核对实际 FR5 的固件、SDK、传感器配置、参考系、零点、负载重力补偿，再在**非人体**仿体台架上测试官方控制器。还需要独立载荷计，因为腕力传感器本身不能既当控制输入又当完全独立的真值。

**R13-10** 是“缺一项就拒绝”的逻辑与：时钟、标定、有序轨迹、独立几何、刮板轮廓、力觉坐标系、零点、时间新鲜度、非人体审批等必须全部满足。工作程和返程还需独立审查力限；从工作程到返程应经过 `UNLOAD`（卸载确认）。`HOLD` 是停留/拒绝状态。代码中 `robot_command=None`，**即使所有布尔字段都为真也不会向机器人发送运动指令**。

## 12. V13 七个接口怎么连起来：把“数据格式”变成“拒绝规则”

软件工程里，接口就像快递包裹上的地址和条码。只写“送一箱东西”不够，还要写从哪里来、给谁、单位是什么、版本是什么。机器人也一样：如果一个模块输出 500，却没写单位是毫米还是米，另一个模块可能误以为是 500 米，后果很严重。

`StrokeIntentV13` 是人工的有序路线：笔划编号、像素序列、方向和分叉选择；缺起点/交叉未确认就拒绝。`SensorEvidenceV13` 包含 RGB/深度/法兰时间戳、时钟域、相机内参 `K`、手眼变换 `T_EC`；不同钟表的时间不能直接相减。`SupportAuditV13` 记录哪里有深度、哪里靠近边界、哪里是连续缺口、图跳数；图跳数只能提示重观测，不能当三维误差。

`GeometryEvidenceV13` 需要局部曲面、独立参考编号、协方差与工具覆盖；没有独立真值就不能标记 validated。`ToolEvidenceV13` 需要实测刮板边缘、TCP 到边缘的变换与版本；换了一块刮板就可能要重新测。`WrenchEvidenceV13` 包含六维力/力矩、时间、参考系、零点和负载；`PhaseReviewV13` 则记录阶段、独立审查的力限和卸载确认。

**故障练习**：假设相机被拆下重装，软件还在用旧手眼外参；即使图片清晰，也必须拒绝资格。再假设力传感器时间戳停止更新，力值看起来稳定；这不是恒力控制成功，而可能是传感器数据过期。报告中的故障注入清单列出了跨时钟、深度飞点、墨线交叉、刮板更换、零点漂移、返程未卸载等应拒绝的情形。

## 14. 统计与安全边界：三张图不等于三千多个独立实验

三张室内图的 3288 个数字标注像素（1482+1003+803）彼此高度相关：相邻像素可能属于同一张桌子边缘或同一条标记。不能把它们当作 3288 个独立被试，给出看似精确的置信区间。更不能用室内场景代表皮肤、呼吸、汗液、反光和柔软组织变形。

这里的 P95 还存在一个陷阱：它只统计可达缺测点，无法到达的点被排除。因此统计表必须同时写“多少缺测点”“多少不可达”“可达样本 P95”“最大岛”。若换了四/八邻接，可达样本集合也换了，不能直接比较两个 P95 的好坏。

误差预算像财务账本：深度、相机内参、手眼外参、时间戳、曲面模型、工具边缘、TCP、力传感器零点和重力都可能贡献误差；其中一些是共同偏差，不会因多拍照片而消失。没有实测误差分布时，任何“95% 安全”都没有根据。

**安全边界**：所有真实机器人接触研究先从非人体台架做起，必须有独立风险评估、急停、机械限位、工作空间限制、传感器失效策略与监护。官方示例的力/速度参数不是人体安全值。返程轻力也不一定优于离面返程，应作为待比较的两种策略，而非先验结论。


**为什么不能把“所有像素”当独立实验？**假设一条墨线穿过一片深度相机无法看清的反光区域，连续 50 个像素都缺失。把它当作 50 次独立失败，会错误地夸大样本量；实际上它们可能是同一个遮挡或材质因素造成的。下一轮统计应以场景、采集会话、相机重装和曲面仿体为分组单位，先在每组计算完整路径误差，再跨组比较。

**风险—覆盖必须成对报告**：若方法 A 接受 90% 的路径，其中 10% 错误；方法 B 只接受 20% 的路径，其中 1% 错误，不能只看 1% 就说 B 全面胜出。应先由非人体任务需求定义“错误”的独立几何阈值，再在相同测试集上比较错误接受率、拒绝率和重观测代价。没有独立参考时，本轮只能报告深度是否非零与图拓扑，不能计算这些风险。

**自测 14**：三个场景 3288 个像素能给出“人群 95% 置信区间”吗？**答案**：不能；既不是人体样本，也不满足独立同分布假设。**进阶**：如果深度非零但在边界产生飞点，点级覆盖率会怎样？**答案**：覆盖率仍算它有效，因此覆盖率不能替代真实几何准确率。

**WP14-A** 先把六个真实 PNG 合法下载到本地，核对 6/6 Git SHA，再用 Python/Pillow 和独立 JavaScript 对每个场景的四/八邻接缺测统计逐项比对。只有这一步实际运行成功，才能把“连接器侧真实结果”升级为“本地双实现真实数据复现”。**WP14-B** 再取得 iBims 激光参考或独立测量的非人体仿体，确认版本、相机尺度、掩码、配准，才能真正比较三维毫米误差和边界误差；两个不同场景不能强行逐像素相减。

**WP14-C** 在非人体弯曲仿体上同时采集人工点选和**真实实体墨线**，记录每笔顺序、起终点、方向和交叉处的选择；两名或更多标注者独立复核，防止“自己标自己评”。**WP14-D** 实测刮板边缘、圆角、安装 TCP 与重复安装偏差，在同一仿体上比较“只检查中心线”和“检查整个工作边缘”哪种更少错误接受。

**WP14-E** 在通过风险评审的非人体台架上核对 FR5 固件和 SDK，读取原始力觉/时间戳、做零点与负载补偿，使用独立测力计比较厂家 `FT_Control` 恒力基线、工作程与返程卸载/轻力/离面方案。观察工作程力跟踪、换向峰值、接触丢失、时间延迟和故障拒绝；任何异常都先停机。**WP14-F** 复核更近的飞点、可靠性深度与多接触研究，只有独立真值和强基线都齐备，才判断博士创新是否真的位于“有条件可信的接触估计+双向控制”。

**进入/退出门**像考试：进入考试需要先准备好仪器、许可和安全；退出考试不是“写了计划”，而是“有原始数据、有对照、有明确通过标准”。具体非人体指标阈值必须在实验前依据测量分辨率、任务需求与安全评审确定，本轮不能凭空给出人体安全力值。
