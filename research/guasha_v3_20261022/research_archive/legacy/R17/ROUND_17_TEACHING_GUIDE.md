## 0. 执行摘要：本轮为什么改变优先级

**学习目标与生活类比**：理解为什么本轮不是继续“改进一个深度网络”，而是先检查实验试卷有没有重复。想象学校把同一张考卷复印两份，分别放进练习集和期末考试；即使学生答得很好，也无法说明会做陌生题。RGB-D 的 RGB 是彩色照片，D 是每个像素到相机的距离；两份完全相同的 RGB-D 是同一张“考题”。

**逐层解释**：R16 的 Middlebury 是真实双目代理，不是 FR5 背部。R17 确实从公开 TUM 仓库取到了原始文件**二进制字节**，但只在连接器中检查 PNG 结构和 CRC，并未在本地重建其像素，也没有机器人运动。`Git blob` 是文件内容在 Git 里的身份标记，`capture_group` 是同一次物理采集应归在一起的组，`annotation_version` 是同一采集可能有多种人工标签。注册是把深度相机看到的点换算到 RGB 相机的坐标；“生成谱系”是回答谁、用哪个脚本和标定参数生成了发布文件。

**算例**：154个文件中一对观测完全重复，并不意味着154条标签中有一条“假”。它们可能来自不同人标注同一场景。重要的是不能把这对图像拆到训练与测试两侧后声称测试完全独立。32.3657%是随机拆开的理论概率，不是已经发现32%的实验出错。**自测与答案**：①“本轮拿到了FR5背部实测吗？”没有。②“9/9 CRC 通过意味着深度准确吗？”不意味着，只证明文件结构完整。③“为什么停止扩大合成排行榜？”缺同场景独立物理真值时排行榜无法回答接触安全问题。

## 1. R16 报告、教学讲义与决策记录：逐项继承但允许推翻

**学习目标与类比**：读懂研究决策不是“老方案永远正确”。医院病例复查会标明“确诊、待查、推翻”，算法研究也应这样。R16 的 `REAL_STEREO_PROXY` 表示真实双目代理证据；`GT_UNKNOWN` 表示没有可评分的参考真值，不等于算法错；`HOLD` 是不放行机器人运动，不是理论已失败。

**逐项教学**：上一轮关于风险—覆盖率、禁止拿真值挑选路径、厂家力控基线和旧仓库禁止写入仍保留。新增证据让我们将“TUM完全拿不到”修订成“连接器能取到字节、容器不能本地复算”。这就是科学修订：不否认已做的工作，也不把部分通过写成全部通过。`ADR-R16-07/08` 还提醒：发现注册代码可疑并不等于发布数据必然错误。

**完整例子**：假设某工厂产品有条形码（blob）、检验单（标注）、机器出厂校准证（标定）。发现两件产品条形码相同却检验单不同，第一步是确认它们是否其实是同一件产品的两份检验单，而不是直接判定有人造假。**自测与答案**：①“保留”与“已实测通过”相同吗？不同。②“本轮哪一层证据升级？”TUM 原始 PNG 字节/结构审计。③“是否可因代码疑点直接修复发布图？”不可，先追生产链与独立靶标。

## 2. 文献、官方接口、数据与源代码证据账本 L17-01—L17-16

**学习目标与类比**：学会“我究竟读到了论文哪一部分”。证据账本就像实验室借书记录：借到封面与摘要不等于读过方法、实验与附录。`I-F` 是上一轮完整文档，`G-M` 是 GitHub 文件目录元数据，`G-B` 是真正的 PNG 字节，`G-S` 是完整源码文本，`D-F` 是官方接口说明，`P-A` 只有摘要，`C-R` 是本地程序实际计算。

**16条来源逐一导读（前半）**：L17-01 给出 R16 的可继承约束；02 是 TUM 数据 README，不能把 README 的154条当作154个独立物理采集；03 是目录中的文件名/大小/blob SHA，能做精确去重但不能做像素近似匹配；04 是9个真实 PNG 的头部/CRC，不能推出像素数值；05 是注册 C++ 完整源码，可指出实参顺序；06 是注册 README，可指出示例输入目录；07 是 YAML 标定数值，不能当作独立外参真值；08 是两份 MATLAB 开发脚本，不能当生产日志。

**后半逐一导读**：09 OpenCV 官方函数定义，决定参数语义；10 Git 官方对象格式，解释为什么 blob SHA 不等于 sha256sum；11 Barz&Denzler 的摘要，说明重复测试样本已有研究，但我们未核读其全文；12 Kaufman 等的摘要，说明数据泄漏并非新发明；13 FR5 力控 API，仅证明功能存在；14 R16 本地 Middlebury 证据不能替代 TUM；15 NIST 说明共模/相关误差；16 2026 汽车图像论文的摘要，说明近重复是跨领域问题，不可套用它的数字。

**自测与答案**：①“L17-11能支持作者方法每一项消融的具体数字吗？”不能。②“L17-04可证明人体毫米精度吗？”不能。③“L17-09为什么优先于博客？”官方签名定义了实际接口契约。

## 4. 真实二进制审计：已取得什么，仍没取得什么

**学习目标与类比**：懂得“文件完整”和“物理正确”的差别。邮寄玻璃温度计时，封条完好只能说明包装没有明显损坏，不能证明温度计读数校准正确。PNG 的 `IHDR` 是文件头，记宽高、颜色类型和每通道位深；`CRC32` 是每个块的传输完整性校验，不是精确三维测量。

**九份实际检查**：三个场景各检查已注册深度、未注册深度、数字笔迹，共9份。深度 PNG 是16-bit 灰度，即一个像素可能有0到65535的整数编码；笔迹是8-bit 索引色，即像素保存调色板编号。它们均640×480，CRC检查均通过。表中缩写 blob（例如 `c597834d…`）只是展示前8位；完整40位见冻结 JSON，不能用缩写代替校验。

**重要边界**：连接器取得真实二进制后在该环境解码了 PNG 的块结构，却没有在本地容器保存这9份 PNG。`LOCAL_PIXEL_REDECODE=FALSE`，因此本轮不能复核 R11 的深度非零率，更不能证明彩深配准。Git blob 哈希计算包含 `blob 文件长度\0` 头；它不是原文件 SHA256。**自测与答案**：①“CRC全过是否说明笔迹能回投影？”不。②“16bit就是16毫米精度吗？”不，位数不等于测量精度。③“为什么记录固定commit？”防止仓库后续修改导致无法复现。

## 6. 组合数学：固定大小随机划分到底有多大泄漏风险

**学习目标与类比**：从零推导“随机拆分时重复试题跑到两边的概率”。`N` 是全部文件数，`m` 是互不重叠的重复文件对数，`t` 是测试文件数，`C(n,k)` 表示从n件物品中挑k件的组合数。`cross` 指一对完全重复文件一份进训练、一份进测试。

**公式逐步讲**：R17-01 先计算“完全不跨界”的组合数。若有j对重复文件都整体放测试，测试集已占2j个位置，剩下的从单独文件中挑；把所有可能的j加起来，再除以总切分数 `C(N,t)`。R17-02 用1减它得到至少一对跨界。R17-03 的期望值是每对跨界概率乘m；它不是“发生泄漏的概率”，因为可能一次跨多对。R17-04 是154文件、唯一重复对、31测试的特例。R17-05 是206文件、8对重复、41测试的精确求和。

**小算例**：4个文件 A1、A2（完全重复）、B、C，随机选2个测试。全部 `C(4,2)=6` 种；不跨界只有 `{A1,A2}` 或 `{B,C}` 两种，所以 `P(any_cross)=4/6=66.7%`。注意这不是机器人运动的失败概率。**自测与答案**：①“为什么95.7568%不等于实际泄漏率？”没有实际训练/测试切分。②“E=2.563对意味着一定至少两对吗？”不是，期望可为非整数。③“如果重复对互相重叠能直接用公式吗？”不能，先构成更大的连通组。


**与研究报告逐字一致的公式 R17-01**：

**R17-01** `P(no_cross) = [Σ_{j=0}^{m} C(m,j) C(N-2m,t-2j)] / C(N,t)`，其中越界组合数取0。

**零基础拆解**：这是在固定测试集大小的前提下计算“所有重复对都没有跨界”的精确组合式；分子按整对进入测试的个数j分类。


**与研究报告逐字一致的公式 R17-02**：

**R17-02** `P(any_cross) = 1 - P(no_cross)`。

**零基础拆解**：“至少有一对跨界”与“没有任何一对跨界”互为补事件，所以相加为1。


**与研究报告逐字一致的公式 R17-03**：

**R17-03** `E[cross_pairs] = m × 2t(N-t) / [N(N-1)]`。

**零基础拆解**：期望跨界对数是各对跨界指示变量的期望之和，线性期望不要求这些事件独立。


**与研究报告逐字一致的公式 R17-04**：

**R17-04** 对唯一一对重复的154个标注条目，`P(cross) = 2×31×123/(154×153) = 0.3236567354`。

**零基础拆解**：154条、31条测试、123条训练且只有一对重复时，恰好一个成员进测试的概率为约32.37%。


**与研究报告逐字一致的公式 R17-05**：

**R17-05** 对8对重复的206个未注册文件，`P(any_cross) = 0.9575677568`，`E[cross_pairs] = 2.5631067961`（测试41/训练165）。

**零基础拆解**：206条、8对重复的结果来自组合数精确求和，不是用独立事件近似相乘；期望值可以大于1。

## 11. 几何误差、相关性与统计验收：不能用文件数冒充样本数

**学习目标与类比**：理解为什么“一百万像素”未必是一百万份独立证据。同一张班级合照里有几十万像素，但只代表同一次拍摄；若相机标定偏了，很多像素会一起偏。统计上的`ρ`（rho）表示同组样本的相关程度，`n_eff` 是“相当于多少个独立样本”。

**公式讲解**：R17-11 是等组大小的近似设计效应：`n_eff ≈ n/[1+(k-1)ρ]`。若每组有2个几乎完全相同样本（`k=2,ρ≈1`），原始100个文件只有约50个独立信息量；不是说一定恰好50次采集。R17-12 是未来算法取舍的成本函数：几何错误、错误接受、重观测、人工确认各有权重。权重不能看完测试结果才改，否则就是用考卷答案设计评分标准。

**完整例子**：A方法接受90%路径，但偶尔把边缘错位几十毫米；B方法只接受75%，其余要求重新拍照。不能只比较接受率，还要同时记录错误峰值、重拍次数和操作者耗时。没有FR5真实批次就不能给出置信区间。**自测与答案**：①“百万像素可直接做百万个独立t检验样本吗？”不。②“ρ=0和ρ=1有何差别？”前者组内近似独立，后者强相关。③“成本权重应何时确定？”独立测试之前。


**与研究报告逐字一致的公式 R17-11**：

**R17-11** `n_eff ≈ n / [1+(k-1)ρ]`（等组大小 `k`、组内相关 `ρ` 的设计效应近似；并非本轮实测参数）。

## 18. 完整术语词典（按研究链路查找）

**RGB**：红绿蓝彩色图像。**D/Depth**：每像素的距离值。**RGB-D**：彩色图与深度图组合，前提是对应关系明确。**Eye-in-Hand**：相机装在机器人末端，跟随末端移动。**FR5**：FAIRINO 五公斤级协作机器人型号；具体硬件能力需按实机版本核对。**六维力觉**：Fx/Fy/Fz 三方向力和 Mx/My/Mz 三方向力矩。**TCP**：工具中心点，数学参考点而非完整板边缘。**SE(3)**：三维刚体旋转加平移。**K**：相机内参矩阵，通常含焦距与主点。**Rt/T**：坐标系之间的刚体变换，必须注明源和目标。**Jacobian/J**：输入小变化如何影响输出的小变化。**Covariance/Σ**：不确定度及其相关性矩阵。**P95**：95百分位，不是最大误差。

**Git commit**：仓库不可变快照标识。**Git blob**：Git文件对象的内容身份，通常以SHA-1命名但并非原文件SHA256。**SHA256**：另一种文件散列。**CRC32**：检测文件块意外损坏的校验码，不是密码学防篡改证明。**PNG IHDR**：PNG图像的宽高、位深、颜色类型等头部信息。**bit depth**：每通道保存的位数，不等于深度测量精度。**indexed color**：像素保存调色板编号。**capture group**：同一物理采集或重复观测必须共同划分的组。**annotation version**：对同一观测的不同人工标注版本。**scribbles**：图像上的数字涂鸦，不是实体墨线。**semantic gt**：语义分类标签，不是独立激光深度真值。**source lineage**：文件由哪些输入、程序、标定版本产生的可追溯链。**registration**：把深度相机坐标映射到RGB图像坐标。**occlusion**：遮挡，目标表面没有被该视角真实看到。**z-buffer**：同一目标像素选择最近深度的可见性机制。**near duplicate**：视觉近似但不一定字节相同的文件。**data leakage**：测试中混入训练时已经见过或不应见到的信息。**holdout**：留出测试，要求评估组独立。**group split**：按采集组而非文件随机划分。**combination/C(n,k)**：从n项挑k项的组合数。**expected value/E**：多次随机结果的平均，不是单次保证。**ρ**：组内相关系数。**n_eff**：考虑相关性后的有效样本数近似。

**OrderedStroke**：人工确定起终点、方向、分叉和序号的有序笔划。**SupportGraph**：像素邻接/深度支持关系图，不等于笔划顺序。**MANUAL_CLICK**：人工点选入口。**PHYSICAL_MARK**：实体表面墨线入口。**HOLD**：证据不足不允许运动。**DATA_BLOCKED**：原始数据/标定/来源不满足资格。**REOBSERVE**：拒绝当前观测并要求重拍。**FT_Control**：厂家恒力控制API。**WORK_FORCE**：工作程受控接触。**UNLOAD_VERIFY**：换向前确认卸载。**RETURN_CLEAR**：离面返程。**RETURN_LIGHT**：轻力接触返程，仅允许非人体对照。**ADR**：架构/研究决策记录。**WP**：可证伪工作包。**B-R/G-B/C-R/P-A**：分别指本地真实字节、连接器真实二进制、实际运行计算、仅论文摘要等证据级别。

## 19. 综合贯穿案例与带答案练习

**案例**：你要让FR5在塑料背部仿体上的黑色实体墨线运动。第一天你只有一张公开的数字涂鸦 PNG 和深度图。正确做法不是直接让机器人刮，而是先记录固定源版本和数据组身份，检查 RGB/深度相机角色、标定、时钟，确认每个有序点是否可见且深度有效，再用独立测量的仿体几何评分。接着测量真实刮板边缘和装夹，最后在非人体独立力台上比较厂家恒力、卸载和离面返程。任何一步失败都进入HOLD或REOBSERVE。

**练习1**：两份文件 RGB 和深度完全相同，笔迹标签不同，是否可分别进入训练/测试？**答案**：不能用于独立泛化评估；应按观测采集组原子划分，标注版本单独记录。**练习2**：为什么 `P(any_cross)=95.7568%` 不是实际泄漏率？**答案**：它假设206条中8对完全重复、随机固定165/41划分；没有实际训练划分。**练习3**：PNG CRC 全通过但 `T_rgb_depth` 方向不明，能否生成可执行轨迹？**答案**：不能，进入DATA_BLOCKED。**练习4**：注册程序变量名与API签名顺序不一致，能否宣称发布图错误？**答案**：不能，需要实际生产日志、原始→成品重生成和独立靶标。**练习5**：厂家FT_Control可以工作，是否直接使用厂家示例力值刮人体？**答案**：绝不可以，先完成非人体独立测力和风险/伦理审查。**练习6**：某算法P95很好，但有一处未观测缺口，是否整段放行？**答案**：不能，完整路径资格失败，应重观测或拒绝。
