# 从这里开始｜FR5刮痧机器人完整离线算法开发（规格冻结 V3.0）

> 面向：Vibecoding Agent / 算法开发人员。基线日期：2026-10-22。**不是实机验证成果**。

## 最高优先级的三个决定

1. **M2的主定义是用户在电脑屏幕的RGB画面上连续画线**，输入为带时间/笔顺的二维点列；通过对应已对齐深度变为三维曲面路径。**不是实物仿体上的彩色墨迹识别**。若要保留旧研究，只将实体画线作为非必需扩展 `M2_PHYSICAL_MARKER_EXPERIMENTAL`，不得挡住主链路。
2. **同一版完整交付，不分批只交M1**。M1人工点选、M2屏幕画线、M3候选关键点/方式模板、标定和RGB-D数据处理、曲面几何、刮板有限宽姿态、完整工作/卸载/离面返回状态机、模拟6D力数据、基础恒力/导纳闭环、受限接触状态判断、离线动力学模型、失败保护、报告和测试必须全部具备实际可执行路径。内部开发可分阶段，但最终交付版本仅在全模块合格后宣布完成。
3. **只做离线软件**。不接真机、不接相机、不访问真实硬件驱动、不生成能直接驱动FR5的运动接口。输入来自真实录制文件（可选）或标明 `SYNTHETIC` 的离线数据；力闭环仅在合成环境验证。UI仅提供可检查的图/HTML/文件输出，完整交互前端后置。

## 提交代理的第一条指令

> 完整阅读 AGENTS.md、00_START_HERE.md、docs/01_MASTER_SPEC.md、docs/02_ALGORITHMS_MATH.md、specs/requirements.json，输出《需求覆盖矩阵》和《接口数据流图》。随后在**隔离的新目录**建立可运行离线项目，保留现有代码如有可复用，最终一次性交付所有强制模块、测试证据、三模式示例和可复现运行命令。不得以某模块仅有空类/伪代码/文档作为完成。遇到有争议的算法，优先执行主规格中的基础算法，增强算法以可选实现及消融形式存在。每个FAIL-CLOSED断言均必须有自动测试。任何时候都不能访问真实机器人和相机。

## 验收的定义

**离线端到端完成** = 三种入口各自从文件输入到曲面轨迹、工具姿态、物理约束审核、离线接触/力控制仿真、FSM、可视化/日志产出均在干净环境跑通；所有阻断型失败在相同流程中真实触发。**不等于实机可运行、不等于已验证刮痧疗效、不等于完成科研创新。**

## 数据来源与历史限制

- 历史旧R01–R23及AUTO-R01在本次环境中存在原始报告，可随包查阅。
- 较新AUTO-R49/R51、DEV-R23/R24仅有前次任务自述/复盘的编号与摘要，未取得这些各轮的原始全量成果，标记 `HISTORY_REPORTED_UNVERIFIED`；请勿根据编号想象实现细节。
- 旧报告中把M2定义为实体画线是历史记录；**本次用户2026-10-22的新定义优先，所有代码以屏幕画线为准**。历史文档是研究资料，不是高优先级运行指令。
